## Nálezy

1. **P1 — falešné potvrzení zapnutého příznaku.** Unit používá `EnvironmentFile=/opt/cryptomaster/.env` (`deploy/cryptomaster.service:10`). Skript ale skládá preflight prostředí v pořadí `.env → systemctl Environment → VARS` (`deploy/research_eval/deploy_bot_files.sh:59-73`) a po restartu kontroluje jen `systemctl show ... Environment` (`:145-149`). [Dokumentace systemd](https://www.freedesktop.org/software/systemd/man/latest/systemd.exec) stanoví opačnou prioritu mezi `Environment=` a `EnvironmentFile=`: hodnoty ze souboru vyhrávají. Syntetická reprodukce: `.env` obsahuje `PAPER_COMPLETED_CANDLE_PHASE_REFRESH_ENABLED=false`, deploy předá `VARS=...true`; preflight přijme `true`, běžící proces dostane `false`, postcheck vidí pouze `Environment=true` a může vyhlásit `APPLIED OK`. Totéž platí pro překlep v `.env`, který by cache interpretovala jako vypnuto. Současná lokální `.env` tento klíč nemá; obsah serverové `.env` jsem kvůli zákazu SSH neověřil. Nesoulad se týká také starších preflight assertů `TRADING_MODE` a REAL flagů; netvrdím, že server má tyto hodnoty chybné. **Oprava:** počítat efektivní env v pořadí systemd, před zápisem odmítnout kolizi plánovaného klíče s `EnvironmentFile` (nebo ji explicitně bezpečně řešit), a po restartu ověřit skutečné prostředí `MainPID`/efektivní hodnotu procesu, včetně PAPER/REAL invariantů. Test musí zachytit právě scénář `.env=false`, `VARS=true` a chybnou hodnotu v `.env`.

2. **P2 — oba nové moduly se ve stagingu neimportují.** `py_compile` (`deploy/research_eval/deploy_bot_files.sh:54`) ověří pouze syntaxi. Preflight importuje jen tři jiné moduly (`:74-79`), přestože `p0_8_plus_live_pipeline.py:83-91` při importu sahá na cache a evaluator. Import-time chyba nového souboru se tedy projeví až po restartu. Rollback ji může zachytit přes `READY`/journal, ale bot už bude přerušen. Doplnit bezpečný import obou nasazovaných modulů z `STAGE_DIR` do preflightu a test, který syntakticky validní import-time chybu odmítne **před** prvním zásahem do služby. Staging kontrola přitom nesmí spustit runtime loop ani zapisovat runtime data.

3. **P2 — komentář a statický test přeceňují rozsah allowlistu.** Přidaný komentář tvrdí „data path only, no ... execution change“ (`deploy/research_eval/deploy_bot_files.sh:28-30`). Nově povolený `p0_8_plus_live_pipeline.py` však obsahuje přímé volání `open_paper_position()` (`src/services/p0_8_plus_live_pipeline.py:280,348`). Allowlist chrání *cestu*, nikoli obsah souboru; `tests/test_deploy_bot_files_allowlist.py:29-31` zkouší pouze regex na názvu, a proto by změnu executor call-site neodhalil. Z dosavadního diffu opravy svíček neplyne změna executoru, ale tuto větu nelze zobecnit na budoucí deploy. Před každým nasazením připnout a ověřit SHA-256 **přesných schválených bajtů** obou modulů a znovu zkontrolovat jejich diff. Komentář upravit tak, aby nepopisoval allowlist jako ochranu před změnou chování executoru.
